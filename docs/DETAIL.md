# 自动交接

上下文用量达到「自定义 token 预算 × 触发比例」时，把交接存档写进项目目录，并在**同一项目（Workspace）**下新建一条对话继续任务。

> 「75%」是自定义预算的比例，**不是模型上下文窗口的比例**。本机模型窗口多为 96 万~100 万 token，按窗口理解会以为几乎永不触发；本插件默认按 150000 token 预算计算，达到 112500 就交接。

## 怎么设置

装好后有四个入口，都落到同一份配置数据：

1. **左侧栏「自动交接」图标 + 中间列面板**：点击侧栏图标直接在中间列打开设置面板，不用进 Settings。这解决「侧边栏看不到入口」的问题。
2. **Settings → 自动交接**：图形界面切换「全自动 / 先询问 / 停用」，并修改 token 预算与触发比例。
3. **`/handoff` 命令**：在输入框直接输入，例如
   - `/handoff status` 查看当前配置（含是否监测中）
   - `/handoff confirm` 切换为「先询问」
   - `/handoff auto` / `/handoff off` 切换全自动 / 停用
   - `/handoff budget 150000` 设置预算
   - `/handoff ratio 0.75` 设置触发比例
   - `/handoff model deepseek/deepseek-chat` 指定交接后新会话的模型（`default` 清除）
   - `/handoff effort high` 指定推理强度（`default` 用模型默认）
   - `/handoff ask on|off` 交接时是否弹卡现选模型
4. **配置文件**：本 bundle 的 `cordis.patch.yml` 提供初始值；界面或命令的改动写入用户 profile 的 `cordis.patch.yml` 覆盖层（升级不丢）。改完由 Loader 自动重载插件生效。

## 交接后新会话的模型与推理强度

新对话默认用 DSH 的默认模型。想指定有两种办法：

- **面板里设默认值**：Settings → 自动交接 →「交接后的新对话」，选模型与推理强度，之后每次交接都套用；
- **交接时现选**：开着「交接时弹卡现选」时，「先询问」模式批准后、或你手动说「开个新对话继续」之后，会先弹两张卡（模型 → 推理强度），只影响这一次。

模型在发首条提示词之前就装好（否则第一轮会用默认模型跑）。选的值必须出现在当前可用模型目录里；装不上（模型下线、凭据缺失、弹卡超时）时交接照常完成，新会话用默认模型，`.NOTICE.md` 会写明原因。

注意：DSH 的模型选择会同时记成默认模型，即之后手动新建的对话也用它。

## 三种模式

| 模式 | 行为 |
| --- | --- |
| `auto`（默认） | 到阈值自动写交接文档、新建对话、发出首条提示词直接开跑，无需手动操作 |
| `confirm` | 到阈值先弹卡询问（含「本代不再提醒」），批准后才执行 |
| `off` | 停用监测；配置入口仍可用，不会删除已生成的交接文档 |

## 触发后发生什么

- 项目目录写入 `PROJECT_STATE.md`（若已存在自动改用带时间戳的名字，**绝不覆盖**）；
- 同一 Workspace 下新建会话，并让它读交接存档后继续任务；
- 旧会话收到一条系统级提示，停止继续推进原任务，避免两个会话并行重复工作；
- 项目目录另写一份 `.NOTICE.md`，记录新会话 ID 与文档路径。

一个会话的一次压缩世代只交接一次；压缩使占用降到 40% 以下可重新武装。子 Agent 会话不触发。

## 已知边界

- 交接文档是**确定性摘要**，不是模型生成的总结；新对话首条提示词会要求它核对项目实际文件状态，并可用旧会话 ID 查证。
- 反查「同项目」依赖 Workspace 归属；若当前会话不属于任何 Workspace，插件跳过交接。
- Client 设置面板为手写免构建模块；首次启用本 Client 半需要重载插件并刷新页面。
- 选模型需要 DSH 提供 `sessionController.modelCatalog()` / `selectModel()`；版本较旧时面板提示「读不到模型目录」，交接仍正常，只是不干预模型。
- `auto` 模式刻意不弹模型卡：全自动不该为了选模型卡在一次 120 秒的超时上。
